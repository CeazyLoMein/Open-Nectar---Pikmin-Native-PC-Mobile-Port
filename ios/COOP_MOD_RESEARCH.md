# Co-op mod comparison and independent player settings

Inspected October26,2026. Research/design only: no new gameplay implementation, mod installation, runtime validation or build dispatch. Public source text read, not executed. Exact inspected public-source blob hashes and retrieval receipt retained in the private workspace work/coop-mod-research/source-receipt.json. Third-party code is NOT copied into this repository. Scope is transferable design, not a claim that these mods are complete or compatible with Pikmin/iOS.

## User requirements and queue policy

New steering ADDS objectives; it does not cancel existing tasks unless the user explicitly says so. Keep the shared objective queue and prior milestones. Independent camera preferences, graphics/FPS/resolution, audio, control mappings/sensitivity and touch layout are CORE co-op requirements. Preserve personal config files and restore personal gameplay values after sessions. Texture packs and genuinely cosmetic skins should be permitted to differ once their rendering-only behavior is verified. Arbitrary mods which alter actors, geometry, collisions or object ordering cannot be called cosmetic solely from their name.

Shared world rules must agree, but both players need not manually configure identical settings. Host sends agreed session-only rules before simulation. Personal settings are not overwritten. Per-player health/invincibility/damage assistance is OPTIONAL if practical; global day length, enemy health, world speed and shared Pikmin population remain coherent session rules. Both simulations could agree on P1-health200% and P2-health100%; matching simulation rules does not require identical player capabilities. This is possible design, not implemented support. A host-owned actor must apply each player's rule by stable player identity; current global cheat getters are insufficient for personal rules.

## Outer Wilds — Quantum Space Buddies

Author project: https://github.com/qsb-dev/quantum-space-buddies ; author distribution/docs: https://outerwildsmods.com/mods/quantumspacebuddies/ . Uses OWML/Mirror. Source inspected: QSB/WorldSync/QSBWorldSync.cs, WorldSync/Messages/RequestInitialStatesMessage.cs, Syncs/SyncBase.cs, ServerSettings/*.cs. It constructs identifiable world objects, checks readiness/hashes, requests initial object states from host after readiness and interpolates non-owned objects. Mod docs warn hierarchy/event changes need explicit compatibility. Useful transfer: stable object registration, ready-then-baseline join, single owner for changes, interpolation and explicit events, local presentation separated from shared state. Mirror/Unity code is not a drop-in for native C++ iOS. Do not expose Outer Wilds story spoilers in user reports.

## Skyrim Together Reborn

Author source: https://github.com/tiltedphoques/TiltedEvolution ; guides: https://wiki.tiltedphoques.com/tilted-online/general-information/faq and https://wiki.tiltedphoques.com/tilted-online/general-information/playguide . Pikmin should not inherit Skyrim's quest-interaction restrictions as a design goal; validate both players' gameplay actions through the host instead.

## Elden Ring — Seamless Co-op

Author primary page: https://www.nexusmods.com/eldenring/mods/510 . Documents changes to existing P2P networking using Steam networking, persistent sessions across deaths/progression, synchronized travel/world resets, separate co-op save files, optional difficulty scaling and same-version/gameplay-mod requirements. Uses existing online-capable game machinery, so it is not evidence that online can be trivially added to a local-only game. Useful transfer: session survives ordinary gameplay events, host governs shared resets/transitions, isolated campaign saves, clear rejoin and opt-in difficulty. Public author page reviewed; low-level proprietary implementation was not available to verify. No FromSoftware code or binaries downloaded.

## New concrete Pikmin restriction found

Actual pc_settings.cpp::pc_settings_netplay_session_begin, around7390 at audit source, forcibly sets fpsMode=0 (30 FPS) because the old session clock and frame clamp are coupled. PC_NETPLAY_SESSION_FIELDS around1141 includes freeCamera, firstPerson, gyroEnabled, coopSplit and coopMergeCamera in addition to gameplay rules, despite the adjacent comment describing camera feel as local. Those settings would be shared/locked if this path were enabled unchanged. pc_netplay_session.cpp::online_guest_replica_ticks also documents render skipping causing item-state divergence at tick12 in an upstream rejoin experiment.

Therefore the old exact-replay path is a PROTOTYPE CANDIDATE, not an accepted final shortcut. It must preserve different personal camera/control/display settings and user's120FPS option; do not silently force30 FPS, copy another player's settings or disable cosmetic packs to claim success. Validate separate simulation clock/presentation and object rules. Existing new iOS content identity already excludes personal settings/cosmetic replacements; it explicitly says gameplay-rule agreement is still needed before simulation starts. Existing host-rule adoption uses temporary config/disk restoration, a useful mechanism to adapt rather than replace wholesale.

## Further multiplayer and service research — 2026-10-28

User requests a polished, game-like two-player experience and asks to account for disconnects, bad internet, invitation friction and other failure cases without dropping earlier objectives. Research examples below supply requirements, not claims that these features are implemented.

- Quantum Space Buddies' author documentation (https://github.com/qsb-dev/quantum-space-buddies) describes a title-menu connection flow and host identity; keep joining discoverable, explicit and private. QSB is not evidence that its Steam path works on iOS.
- Skyrim Together's feature guide (https://github.com/tiltedphoques/gitbook-wiki/blob/main/general-information/features.md) documents party-leader dialogue, synchronized inventory and world time, and warns follower ownership can make followers wander. Its 1.8.4 release (https://github.com/tiltedphoques/TiltedEvolution/releases) documents fixes for broken party progression, stuck cutscenes and delayed movement. For Pikmin, use host-authoritative shared events, preserve per-player squads, deduplicate deliveries, and test both users initiating an action; avoid requiring the host to do all interaction merely because another mod does.
- No Man's Sky developer patch notes (https://www.nomanssky.com/synthesis-update/ and https://www.nomanssky.com/expeditions-update/) explicitly list desync, invisible partners, stuck interactions after disconnect and blocked progression fixes. Treat these as concrete failure modes and regression cases, not blanket judgment about the game.
- Unity's session guidance (https://docs.unity.com/en-us/mps-sdk/join-session and https://docs.unity.com/en-us/mps-sdk/session-host-migration) distinguishes a reconnectable member, an expired/deleted room, host election and actual world-data migration. For this project keep a frozen host world on guest loss, re-authenticate, send a complete baseline and require both ready before resuming; host death requires a real restorable checkpoint, not simply promoting Raye or promising exact recovery.
- Valve's official networking documentation (https://partner.steamgames.com/doc/features/multiplayer/networking and https://partner.steamgames.com/doc/api/steamnetworkingtypes) describes relays and delay uncertainty. An iPhone relay service/credentials are not established merely by using open-source GameNetworkingSockets. Do not claim internet-wide play until tested on different networks. Measure actual delay, loss and snapshot health before offering actionable network quality feedback; do not label a single transient latency sample as failure.

Acceptance queue: legible game-themed safe-area UI on small and large devices; accessible controls and clear states for checking data, hosting, connecting, partner ready, starting and interruptions; user-initiated system share for invites with no secret in logs; rejoin without resending when valid; recoverable retry when a code expires; no app restart if early exit is safe, clear restart wording until scratch-card lifetime is solved; preserve personal settings and cosmetic content; explicit solo and shared campaign slots with verified backups; atomic shared Onion and unique reward handling; reliable transition barriers; background, Wi-Fi to mobile, low connectivity, duplicate action, device sleep, host quit/crash and save-failure tests. Current practice remains disposable and is not campaign co-op.

## 2026-10-28 — Display smoothness and packet behavior research

Primary network explanation: https://gafferongames.com/post/snapshot_interpolation/ documents that even regularly sent snapshots arrive with jitter, and interpolation trades a controlled amount of display delay for smoother movement. https://gafferongames.com/post/state_synchronization/ stresses keeping authoritative simulation state separate from visual correction. For this project, code audit shows practice currently publishes complete actor keyframes every 50 ms and applies the latest directly to the guest models; this can produce visual stepping independently of input lag. Real hardware must distinguish it from packet delay, missing frames, camera/render failure and 120-vs-60 FPS.

Do not simply change reliable snapshots to unreliable: CoopSession currently uses one globally increasing sequence and explicitly accepts reliable ordered events only, while a full actor frame is fragmented and must be assembled and validated atomically. Different delivery requires a revised per-stream ordering contract, complete-frame loss and stale/reordered safety, independent control reliability, bounded memory and full resync, followed by impaired-network testing. Valve's official https://partner.steamgames.com/doc/api/steamnetworkingtypes describes reliability, batching and packet-loss behavior; transport capability does not by itself give iOS a Steam relay service.

Added an isolated candidate `blendPracticeVisualFrame`, not called by runtime: validated frame inputs, bounded actor counts, latest-frame metadata, stable entity-ID pairing, shortest-angle turns, safe snaps on large position jump or action/color change, immediate births/removals and atomic rejection of invalid values. It intentionally does not smooth game authority, collisions, input, save or actual recovery. 26/26 local network tests, encrypted loopback and strict Clang passed. No Apple build, on-screen appearance, performance or iPhone result. Next determine a full snapshot/interpolation-clock policy with explicit pause/disconnect/lifecycle handling and retain exact authoritative state; only integrate after engine-view fixtures and timing tests. Build81 remains a separate iOS build; this candidate is not in it.


### Background, discovery and honest recovery (2026-10-28)
- Apple documents that Multipeer Connectivity closes its sessions on background; it is not an automatic solution to our resume problem. It is also deprecated in Xcode 27 in favor of Network framework. Our current transport is not Multipeer Connectivity; do not apply its exact lifecycle behavior to our transport. Sources: https://developer.apple.com/documentation/multipeerconnectivity and https://developer.apple.com/documentation/technotes/tn3213-moving-from-multipeer-connectivity-to-network-framework
- Apple local network privacy requires designing for denied/undetermined access and an understandable user remedy, rather than mislabeling every connection failure as bad Wi-Fi: https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy
- Outer Wilds QSB explicitly warns that hierarchy changes and gameplay events from mods may break sync, and documents timeout/setup tradeoffs. Cosmetics may remain local if verified presentation-only; do not assume arbitrary mods are compatible. Source: https://github.com/qsb-dev/quantum-space-buddies/blob/master/README.md
- A remembered room invite is in memory, not guaranteed after force quit; it can expire or its host can close it. Treat Rejoin Last Room as a best-effort convenience, not live world rejoin or guaranteed resume.


### Cross-device saves and player identity
- Larian describes cross-save as copies of recent local saves synchronized through an account; cloud copies have retention limits. The applicable design lesson is that a transferable shared campaign needs local verified backups and clear version/conflict handling, not a promise that a cloud service is permanent or that copying a day-end save recreates a live battle. https://larian.com/support/faqs/larian-account-information_49
- Larian also documents an already-connected multiplayer failure when copied profiles share a player UUID. For our future transfer, separate transferable campaign progress from unique device/player identity, private keys, invite credentials and personal preferences. Validate identity collisions on join and never silently overwrite local saves. This is a design inference from their reported issue, not a confirmed Open Nectar bug. https://larian.com/support/faqs/multiplayer-error-joining-failed-you-re-already-connected_104
- Stardew Valley's official guide starts an existing hosted save through an explicit Co-op menu. Our desired main-menu co-op entry and clear host-owned shared slot align with that workflow, but existing P1 save routing must be examined before promising campaign support. https://www.stardewvalley.net/multiplayer-troubleshooting-guide/


### Across different networks: verified limits and design candidates
- Current iOS room UI explicitly sets `automaticPortMapping = false` and `includeLanEndpoint = true`; its same-Wi-Fi success is not evidence of internet reachability. The room library has optional port-mapping and manual endpoint support, but that is not an integrated, tested iPhone internet solution.
- ICE tests candidate network paths; TURN supplies a relay when a direct path cannot be established. Both need suitable signaling/infrastructure and operational authentication; no available relay or cost is assumed. Evaluate privacy, operating cost, IPv4/IPv6/cellular/Wi-Fi switching, expiry, denial of access and connection recovery before selecting a provider. References: https://datatracker.ietf.org/doc/html/rfc8445 and https://datatracker.ietf.org/doc/html/rfc8656
- Apple distinguishes local-network permissions from cellular or VPN interfaces; network error guidance must distinguish denied local access, failed discovery and unreachable host when possible, instead of claiming that every failed internet attempt is a Local Network permission failure. https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy
- Do not quietly enable router mapping, a new hosted relay, or any account service while studying. These need an explicit usable design, tests, and user visibility; current authority already allows routine project development.
