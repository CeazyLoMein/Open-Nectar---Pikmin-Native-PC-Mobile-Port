## What we learned from comparable games

| Reference and primary evidence | Relevant lesson | Our decision |
|---|---|---|
| [Pikmin3 Deluxe — Nintendo's leader/squad guide](https://play.nintendo.com/news-tips/tips-tricks/pikmin-3-deluxe-tips-story-mode/) | Players can command separate leaders and divide squads toward shared objectives. This documents local co-op gameplay, not an online architecture. | Each phone gets its own captain, full screen/camera and owned squad, with free separation in one area. |
| [Stardew Valley — developer multiplayer FAQ](https://store.steampowered.com/news/posts/?appgroupname=Stardew+Valley&appids=413150&enddate=1551465789&feed=steam_community_announcements) | Farm/world progress and money are shared while player inventories/skills remain separate. It explicitly coordinates day transitions and provides host-wide pause. | Shared campaign/Onions; per-player allowance and controls. Explicit shared pause and readiness, with phone-interruption protection. Area travel may pull both along as user accepted. |
| [Factorio — latency hiding](https://www.factorio.com/blog/post/fff-83) and [megapacket postmortem](https://www.factorio.com/blog/post/fff-302) | Responsive local presentation can be separate from official state. Unbounded buffered/repeated actions can cause a traffic feedback loop. | Predict only suitable local movement/aiming; host confirms inventory/damage/production. Bound update cadence and traffic/backlog; don't replay arbitrarily many stale actions. We are NOT adopting Factorio's deterministic-lockstep architecture. |
| [Mindustry — developer-owned server source](https://github.com/Anuken/Mindustry/blob/master/core/src/mindustry/core/NetServer.java) | Server code sends periodic entity snapshots in bounded batches and synchronizes team resource state. This is a useful mobile/RTS implementation reference, not proof it fits unchanged. | Host sends authoritative actor/resource state; guest displays replicas. Use stable IDs and complete-frame rules already implemented. No external game code/assets copied. |
| [Deep Rock Galactic — developer update history](https://www.deeprockgalactic.com/updatesold) | Developer notes describe teammate status indicators, laser-pointer resource feedback and personal waypoints. | Add a compact partner indicator and explicit Here/Danger/Help/Carry markers, rate-limited and temporary, without issuing Pikmin commands. |
| [Grounded — developer Shared Worlds notes](https://grounded.obsidian.net/news/grounded/grounded-heads-into-the-home-stretch) | Its shared campaign can have one active host; cloud world access also permits friends to host separately. | Keep one official active campaign/save and make its host/save status visible. Independent offline progress/cloud-host switching remains deferred per user. We are not adding Grounded-style cloud hosting in this batch. |

These sources establish individual gameplay/networking lessons. They do not reveal every game's internal architecture, establish a popularity ranking, or prove that our port is playable. Our adaptation choices above are engineering judgments.

## Intended player experience

1. Main menu has an explicit experimental Co-op choice. Create/continue a named shared campaign or Join a private invite. Ordinary solo saves/settings remain intact; initial prototype uses disposable campaign data. No fourth free-profile app required.
2. Host shows game/version, campaign/area/day, selected captains, gameplay rules and each player's allowance. Guest receives a plain explanation for a build/content mismatch. Source/protocol/content identities must be real generated digests, not current shared CFBundleVersion=1. Independent graphics/FPS/control settings are local; simulation-affecting mods/rules must match. Visual-only packs can differ only after checking they don't alter simulation assets.
3. Each controls one captain and squad, including work ownership. Thirty per player means60 total when the engine's safe global cap permits it. Shared Onions are processed atomically by the host; pending withdrawal waits for acknowledgement rather than spawning predicted extra Pikmin. Dismissed/working Pikmin still consume the owner's allowance.
4. Normal whistle and the separate Recall All cheat operate on that player's owned Pikmin, with normal behavior within their scope; partner workers are not stolen. Optional squad handover should be an explicit accepted transfer. Follower rescue remains host-authoritative and restricted to eligible owned followers. Do not rewrite that working solo feature while adding network ownership.
5. Each phone draws its own full-screen camera and spatial audio from its own perspective. No split/merged view or forced proximity within one area. Camera, precise aim, touch layout and graphics remain personal choices.120FPS stays selectable; actor transfer cadence is separate from display FPS. Actual high-FPS co-op interpolation/host clock still needs engine implementation/testing.
6. Add a compact partner name/color/direction/distance plus health/squad status. A separate partner/ping control offers Here, Danger, Help and Carry; no accidental whistle/recall or automatic camera movement. Markers expire and never command AI. Only one latest marker per person avoids clutter. Haptics/sounds, marker drawing and touch button remain UI work.
7. Both confirm Ready after initial loading and after recovering from interruption. Either may request pause; one cannot clear the other's pause. Settings/manual pause freeze the official world. Backgrounding/lock/call removes readiness; returning requires confirmation rather than resuming mid-fight. The host must stop world advancement, while network handling continues during pause. Engine/iOS lifecycle hooks still need wiring.
8. Separate local menus from shared decisions deliberately. Before day end, show combined progress, losses/strays and safe save status. Coordinate sunset/cutscenes/group travel; warn before pulling the partner into a new area/cave. User accepts forced group travel, so independent simultaneous floors/maps are unnecessary. Synchronized start/countdown must use the accepted scene/start tick, not unrelated phone wall clocks; that glue remains to implement.
9. A dropped guest freezes the host world and preserves the squad/jobs/positions there. Rejoin re-authenticates the intended partner, receives a complete current world, then re-readies. Do not silently replace the guest with a bot, continue alone, clear ownership or accept old packets. The new protocol's actor baseline is NOT a full-world reconnect snapshot. A secure reconnect token and full engine reconstruction remain outstanding.
10. Host owns progress and together-only campaign saving. Both see actual successful save acknowledgement. Build exact-scene snapshot recovery shared with future solo autosave: versioned, validated references, rotating last-good files, safe tick boundary, atomic write, corruption/fallback checks. Never claim an actor-coordinate frame is a save. No periodic normal card write or ship-return compromise added here.
11. Co-op difficulty is mainly tunable health, locked for the session/encounter so enemies don't gain health during a fight. Avoid blanket enemy/population doubling. Initial connectivity tests use a small familiar area and conservative actor budget; tune balance only after verified two-phone combat/performance. Selected extra enemies may come later with measurements.
12. Show a simple connection indicator and reason for waiting: loading, partner not ready, paused by partner, reconnecting or build mismatch. Detailed metrics can join the optional performance HUD. Clear host/guest labels and save status should not require technical knowledge.
13. Native iOS encrypted transport/permissions, same-Wi-Fi discovery/session flow, then private internet joining/relay fallback must be proven on BOTH devices. No assumptions that a direct public address/router mapping always works. Provider/relay deployment and any paid cost need a concrete reviewed choice. No background monitoring/service was deployed.

## Implemented in this source batch

New nectar_net CoopSession binds existing GatedTransport + compatibility gate + previous complete actor-frame receiver. It refuses pre-authentication, missing protocol capability, unknown build/content identity and invalid session/scene. Host-only data publication and world-advance permission, guest-only command permission. Real P1 engine hooks/UI remain inactive.

- Loaded baseline AND explicit Ready from both players before Running. Engine confirmWorldLoaded must attest the complete actual world; currently only actor fixtures exercise it.
- Distinct manual/settings/background blockers. Pause reasons belong to each player. Background removes readiness; foreground never auto-readies. Role-derived sender ownership blocks a guest changing the host's pause or marker identity. Transport role must match session role; repeated unchanged Ready/Loaded/pause UI calls are idempotent and generate no new messages.
-500ms heartbeat,3s timeout. Timeout is checked BEFORE draining old queued messages. Missing peers retain last complete actor replica and cannot silently resume; explicit re-authentication/new accepted scene+fresh baseline+two ready checks is tested. World save/reconstruction/rejoin token not implemented.
- Actor packet transfer through authenticated gate and normal message envelope. Entire set validated before send, at most20 updates/s; known reliable backlog64KiB defers a WHOLE update. Simulation ticks cannot rewind. No forced render FPS change. Queue metrics unavailable from a future transport will require that transport's own queue limits; this doesn't guarantee all lower-level queues are bounded.
- Here/Danger/Help/Carry markers: one latest per player,8s lifetime,1s cooldown, finite/in-range coordinates, validated player identity. They change no squad ownership, tasks, save or world simulation. Coordinates still need future engine ground/occlusion/scene UI validation before drawing.
- Protocol message IDs67/68/69 for control/status/marker, capability0x10000 required by this session wrapper. Existing online flags remain off, no socket/engine mode automatically starts.

## Additional integration checks from the design review

The host must update enemies, hazards, workers and collision around BOTH separated captains; its camera/offscreen/AI culling must never freeze the guest's nearby world. Guest rendering visibility is local and separate from what the host simulates. Test both players on opposite sides of an area, jointly carrying/fighting, simultaneous Onion requests, independent work/recall and coordinated travel. Preserve captain-specific spatial audio rather than mixing both listeners.

CoopSession borrows its GatedTransport. Call end() and stop all session access before closing the owning Room or cancelling GuestJoin; a new transport needs a new session wrapper. No dangling room/session references. Network queue checks apply to measured backlog; the future native transport must enforce its own byte/queue limits. Neither core session permission nor a marker packet automatically pauses/draws game state until engine/UI hooks are connected.
